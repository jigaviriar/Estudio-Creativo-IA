## Resumen de decisiones clave

| Decisión | Alternativa considerada | Por qué esta opción |
|---|---|---|
| Bedrock (API gestionada) | Modelo open source auto-alojado | Arranque rápido, cero mantenimiento de GPU, coste por uso |
| Streamlit | React/Next.js a medida | Prototipado rápido en Python, alineado con el resto del stack (boto3) |
| Roles simplificados por selección (sin login real) | Amazon Cognito | Suficiente para un MVP interno; se documenta como mejora de producción |
| RAG opcional sobre guía de marca | RAG siempre activo / sin RAG | Solo aporta valor cuando hay una guía de marca real que seguir; se deja como opción activable |
| Cifrado local con Fernet | Sin cifrado / KMS | Cubre el requisito de "cifrado de imágenes y contenido" sin la complejidad de gestionar KMS en un MVP |
| Auditoría de llamadas a Bedrock en pestaña separada + log `jsonl` en disco | Mostrar modelo/latencia/tokens inline en el feed de chat | El feed es para el equipo de marketing (diseñador/redactor/aprobador): mezclar ahí detalle técnico (Request ID, tokens, JSON de request/response) lo ensucia para su uso real. Separarlo en "Auditoría" mantiene el chat limpio y da, además, una vista dedicada — con métricas y filtro por tarea — para demostrar que la app consume los modelos de verdad |
| Botón "Borrar todo y empezar de nuevo" con checkbox de confirmación | Borrado silencioso de un clic / sin función de reinicio | El feed es persistente y compartido (no por sesión), así que un borrado accidental afecta a todo el equipo; la confirmación explícita evita ese riesgo mientras permite limpiar datos de prueba antes de grabar la demo |
| Borrado de la auditoría independiente del reinicio del feed | Un solo botón que borre todo (feed + auditoría) | El log de auditoría (`logs/bedrock_calls.jsonl`) solo crece (append-only) y no se veía afectado por "Borrar todo"; separarlo evita borrar evidencia de llamadas reales por accidente al limpiar solo el feed de trabajo |
